# botyara

Учебный HTTP-клиент и сервер на Python. Сервер хранит колбэки и задачи в SQLite,
а клиент получает и выполняет только `whoami`, `ip` и `exit`.

## Как это работает

1. Клиент отправляет известный серверу payload UUID через `POST /checkin`.
2. Сервер создаёт callback UUID для конкретного запуска.
3. Клиент раз в несколько секунд запрашивает свою очередь через `POST /poll`.
4. Сервер возвращает первую задачу этого колбэка.
5. Клиент выполняет разрешённое действие и отправляет результат в `POST /results`.
6. Сервер сохраняет состояние и результат в SQLite.

Один payload можно запустить несколько раз. У запусков будет общий payload UUID,
но разные callback UUID и отдельные очереди задач.

```text
payload
├── callback A ── whoami, exit
└── callback B ── ip, exit
```

## Установка

Открой папку `botyara` в VS Code, затем открой терминал PowerShell и выполни:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Первая команда создаёт отдельное окружение `.venv`. Вторая устанавливает Flask,
Requests и psutil только в это окружение.

## Запуск

Открой первый терминал и запусти сервер:

```powershell
.\.venv\Scripts\python.exe .\server.py
```

Оставь его работать. В терминале должна появиться строка:

```text
Running on http://127.0.0.1:5000
```

Открой второй терминал и запусти клиента:

```powershell
.\.venv\Scripts\python.exe .\client.py
```

Клиент напечатает свой новый callback UUID и продолжит работать. Не закрывай этот
терминал, пока хочешь отправлять клиенту задачи.

Открой панель в браузере:

```text
http://127.0.0.1:5000/
```

Выбери активный колбэк, команду и нажми **Отправить**. Дождись следующего опроса
клиента (обычно несколько секунд) и нажми **Обновить**, чтобы увидеть результат.

Для проверки нескольких клиентов открой ещё один терминал и ещё раз запусти:

```powershell
.\.venv\Scripts\python.exe .\client.py
```

У двух запусков будут разные callback UUID.

Для удобства также есть `run-server.cmd` и `run-client.cmd`: их можно запускать
двойным щелчком или из PowerShell. Они сами переходят в папку проекта и используют
Python из `.venv`. Сначала запускай сервер, затем клиента.

## Sleep и jitter на клиенте

Это параметры паузы, отдельные программы или библиотеки устанавливать не нужно.

- **Sleep** — базовая пауза между циклами опроса сервера, в секундах.
  `time.sleep(...)` приостанавливает текущий поток Python; компьютер продолжает работать.
- **Jitter** — случайное отклонение от этой паузы. В этом клиенте оно задаётся
  долей единицы: `0.3` — это 30%, `0.2` — 20%, `0` — без разброса.
  При нескольких клиентах это помогает разнести их запросы по времени.

В начале `client.py` настройки читаются из переменных окружения:

```python
SLEEP = float(os.environ.get("BOT_SLEEP", "5"))     # базовый интервал, сек
JITTER = float(os.environ.get("BOT_JITTER", "0.3"))  # 30%
```

`os.environ.get` читает значение переменной. Если её нет, берёт значение справа:
`"5"` или `"0.3"`. Переменные окружения хранят строки, поэтому `float` превращает
их в числа. По умолчанию пауза будет **от 3,5 до 6,5 секунды**: 30% от 5 — это 1,5.

Функция расчёта паузы:

```python
def next_sleep(sleep=SLEEP, jitter=JITTER):
    jitter = min(max(jitter, 0.0), 1.0)
    delay = random.uniform(sleep * (1 - jitter), sleep * (1 + jitter))
    return max(0.1, delay)
```

- `min(max(...))` ограничивает jitter диапазоном 0–1: отрицательное значение станет
  нулём, а `1.5` станет `1.0`, то есть 100%.
- `random.uniform` каждый раз выбирает случайное число между нижней и верхней границей.
- `max(0.1, delay)` оставляет минимальную паузу 0,1 секунды.

В конце цикла `run()`:

```python
delay = next_sleep()
print(f"Сплю {delay:.2f} сек", flush=True)
time.sleep(delay)
```

`:.2f` показывает две цифры после точки, `flush=True` сразу выводит строку в терминал.
Можно увидеть, как пауза меняется. Время самого HTTP-запроса и выполнения команды
прибавляется к паузе, поэтому это не точное расписание запросов.

Сначала запусти сервер в первом терминале, как описано выше. Во втором терминале,
открытом в папке проекта, задай настройки и запусти клиента:

```powershell
$env:BOT_SLEEP = "8"
$env:BOT_JITTER = "0.2"
.\.venv\Scripts\python.exe .\client.py
```

Получатся паузы **от 6,4 до 9,6 секунды**. Пиши `0.2`, а не `20` и не `20%`;
дробные числа вводи через точку. Для sleep используй положительное число секунд.

Переменные остаются в текущем терминале до его закрытия или изменения значений.
Клиент читает их при запуске. Для изменения останови его через `Ctrl+C`, задай новые
значения и запусти снова. Новый запуск получит новый callback UUID — выбери его в панели.
Через панель sleep/jitter не меняются. `run-client.cmd` также получает переменные,
если запустить его из этого же терминала.

Вернуться к значениям по умолчанию в текущем PowerShell:

```powershell
Remove-Item Env:BOT_SLEEP, Env:BOT_JITTER -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe .\client.py
```

Эта команда удаляет только две переменные окружения текущего терминала.
Проверка `max(0.1, delay)` не заменяет проверку настроек: отрицательный sleep сведётся
к паузе 0,1 секунды, а нечисловое значение вызовет ошибку при чтении. Вводи обычные
положительные секунды и jitter от `0` до `1`.

Сервер считает клиента «не на связи» после **15 секунд без запросов** и в таком
состоянии не принимает новые задачи для него. Значения по умолчанию оставляют запас.
При больших паузах клиент может продолжать работать, хотя
панель временно показывает «нет связи». Изменение этого порога потребует отдельной
настройки серверной логики. Команда `exit` тоже будет получена при следующем опросе,
а `Ctrl+C` позволяет остановить клиента во время паузы.

## Команды

- `whoami` — имя пользователя, от которого запущен клиент;
- `ip` — локальные IPv4 и IPv6 сетевых интерфейсов;
- `exit` — отправить результат серверу и завершить выбранного клиента.

## Остановка и повторный запуск

Сервер или клиент можно остановить сочетанием `Ctrl+C` в нужном терминале.

После перезагрузки компьютера сначала снова запусти `server.py`, затем `client.py`.
Каждый новый запуск клиента регистрирует новый колбэк.

При первом запуске сервер автоматически создаёт рядом с кодом файл `server.db`.
Он хранит историю. Удаление этого файла при остановленном сервере создаст новую
пустую базу при следующем запуске.

## Если что-то не работает

**В панели нет активного колбэка**

Проверь, что второй терминал с `client.py` открыт и продолжает работать. Затем
нажми **Обновить** в панели.

**Задача остаётся в ожидании**

Проверь, что она назначена текущему callback UUID. Новый запуск клиента не получает
задачи старого колбэка.

**PowerShell не находит `.venv`**

Убедись, что терминал открыт именно в папке `botyara`, и выполни установку заново.

**Порт 5000 уже занят**

Скорее всего, сервер уже запущен в другом терминале. Найди его и останови через
`Ctrl+C`, затем повтори запуск.

## Что здесь называется API

API — это способ, которым программы обращаются друг к другу. В этом проекте
это HTTP-маршруты Flask-сервера и формат JSON-запросов и ответов.

Клиент вызывает `requests.post(...)`, а сервер принимает запрос функцией,
помеченной `@app.post(...)`. Например:

1. `POST /checkin` — клиент регистрирует свой запуск и получает callback UUID.
2. `POST /poll` — клиент передаёт callback UUID и спрашивает, есть ли для него задача.
3. `POST /results` — клиент передаёт номер задачи и её результат.

На запрос `/poll` сервер может вернуть `{"task": null}` — задач пока нет.
Если задача есть, ответ содержит её номер и команду. Это общение клиента и сервера
и называется использованием API. Всё уже реализовано в `client.py` и `server.py`.

Страница `/` показывает человеку форму и таблицы в браузере; маршруты API
передают данные программам. Оба варианта обслуживает один Flask-сервер.

## Основные маршруты

| Метод и адрес | Назначение |
|---|---|
| `GET /ping` | Проверка доступности сервера |
| `POST /checkin` | Регистрация нового запуска |
| `POST /poll` | Получение следующей задачи |
| `POST /results` | Сохранение результата |
| `POST /tasks` | Создание задачи через JSON |
| `GET /state` | Получение состояния в JSON |
| `GET /` | Веб-панель |

## Ограничения

Проект предназначен для локального обучения и слушает только `127.0.0.1`.
Клиент выполняет фиксированный набор действий; произвольной командной строки,
автозапуска, загрузки файлов и скрытого режима нет. Payload UUID служит проверкой
по списку известных значений, но не заменяет полноценную аутентификацию.

Задачу можно создать только для колбэка со статусом `на связи`. После закрытия
клиента старый callback UUID остаётся в истории, но новые задачи ему не назначаются.
